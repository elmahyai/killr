The `emV`, `emVEI`, `emVEV`, `emVII`, `emVVI`, and `emVVV` functions call `estepX`, `meX`, and `mstepX` for their model. `emVEV` ends with `meVEV`, not `mstepVEV`. `emEVV` calls only `estepEVV` and `meEVV`. Translate those helpers first; a `em*` function waits until they are translated.

`emE` ends with `meE` as well, not `mstepE`, so it returns the `meE` list. Its noise call needs `Vinv` near 0.3 with `sigmasq` 0.8, or `meE` returns `returnCode` -3 and every value is NA. The same trap hits `emVEI`, `emVEV`, `emVII`, `emVVI`, and `emEVV`: with the proof's scales, `Vinv` 0.15 gives code 9 or -3, and every value is NA. `Vinv` 0.1 gives code 0 for all five. Check that a proof case is not all NA before trusting a match, since NA equals NA in the compare.

`em` (the dispatcher in `R/mclust.R`) checks the name with `checkModelName`, then calls `em<modelName>`. The four single-component names X, XII, XXI, and XXX call `emX`, `emXII`, `emXXI`, and `emXXX`, which take no `parameters` and ignore them through `...`, so their proof passes `NULL` parameters. The other 16 models need `parameters`; the proof builds them once with `mstep` on the fixed `z`, outside the timing. When `control` is missing, the Python `em` uses `em_control()`, which is R's `emControl()` default.

`emEEE` and `emEEV` also return the `mstep` list, after replacing `z` with the `me` result. `meEEE` names the factor `cholsigma`; the `emEEE` return uses `mstepEEE`'s name `cholSigma`. `mstepVVV` returns `cholsigma` in the variance list, as R does, so `emVVV` matches that R field. Its missing-z list has `cholsigma` NA and no `sigma`; on failure it leaves `pro` unchanged.
