R's `boot.rq.pwy` is dense, not sparse. Its Fortran `pwy` solves each augmented LP with the simplex `rq0`, so the exact answer is the rq.fit.br answer. Running it on srqfn leaves a gap of about 5e-6 from R, because srqfn stops at gap `small = 1e-6`. boot.rq.spwy is the sparse one: srqfn matches R's spwy to 4e-14. Check which kernel R calls before choosing a route for a bootstrap.

The port of `rq0` in crates/quantreg_rq0 matches R's pwy exactly (max diff 0.0 on 600 values, and on 8 random designs with ties). Two pitfalls when proving it. Run R with `LD_PRELOAD=/usr/lib/x86_64-linux-gnu/blas/libblas.so.3`, the reference BLAS; `LD_LIBRARY_PATH` does not change the BLAS R loads. Time only the `boot.rq.pwy` call with the replicates built once, because the pure-Python RNG draws otherwise dominate the Python time.
