formulaic 1.2.2 cannot take a `Surv` object as a response column. It fails in `find_nulls` with `FactorValues`, so `survreg.py` evaluates the `Surv(...)` arguments with formulaic and calls `survival.surv.Surv` itself. `model_matrix(..., na_action="drop")` keeps the original row labels of the kept rows, which is the `na.omit` mask; the response, weights, offset, and strata are checked against that mask. `Formula(...).rhs` drops `-1` and `0`, and keeps `1` only when the intercept is present, so the rebuilt right-hand side needs that check. Its string levels are sorted, with the first level as the reference, which matches R's `factor()`. Multi-variable `strata()` groups are the sorted tuples of level codes, as R gives them. `strata.py` `_as_factor` ranks character values by first appearance, so `survreg.py` does not call it. A level order other than alphabetical is not kept: formulaic sorts the string values, so the reference level and the treatment contrasts differ from R's `factor(levels=)` or ordered factors. `ordinal/clm_frames.py` encodes each level as a zero-padded index string, so the sort gives the level order, and maps the column names back to the level labels.
