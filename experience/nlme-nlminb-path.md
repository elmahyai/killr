`lme` calls `nlminb(par, -logLik)` with no gradient, so R's path comes from PORT (drmnf): forward differences with step `sqrt(eps) * max(|x|, 1)`, an identity start Hessian, and a step bound of 1. The first trial is the steepest-descent step of length 1 along that gradient. The analytic Newton step that `lme` used before leaves R's path at that trial. The value-only kernel call is `mixed_loglik` with settings `(REML, 0, 0, pdClass)`. Later forward-difference steps are not `sqrt(eps) * max(|x|, 1)`: at the seventh trial point R uses steps of about 1.68e-5 on all three parameters, and that rule is not reproduced yet. A forward difference divides a one-ulp change in `logLik` by its step, so the kernel has to be bit-equal to R. `dqrdc2` and `dqrsl` in `nlmemixed` now call libblas `dnrm2`, `ddot`, and `daxpy`, as `nlmegls` does. One ulp remains at the start point, so the first trial is still about 2e-5 off in the parameters.

`lme` takes `weights = varFixed(~invwt)` now, so `glmmPQL` passes it directly. Pre-scaling the columns by `1/sqrt(abs(invwt))` does not reproduce R's weighted fit even in R: at glmmPQL's first iteration, `lme(..., weights = varFixed(~invwt))` and `lme` on the pre-scaled columns differ by up to 3e-8 in fixef, 3e-8 in sigma, 3e-7 in the variance parameter, and 7e-7 in fitted values. R's weighted path differs because a `varStruct` makes `length(lmeSt) > 1`, so there is no single `MEdecomp` and `recalc` runs at each objective call, and `logLik` adds the varFixed term `sum(log(w))`. The weighted path in `lme_formula` (varFixed only) matches R within 4e-15 on Orthodont with the same nlminb counts. It skips `MEdecomp`, scales the raw condensed model by `w` at each objective call, and adds `sum(log(w))` (summed in long double) to the log-likelihood. The random structure is initialized on the unweighted model, and fitted values come from the unweighted model.

The `pdDiag(Asym + R0 ~ 1)` case is not a logic gap. Its PORT path is chaotic at the ulp level: forward differences divide a logLik difference of about 2e-13 by a step of about 2.5e-8, so the gradient moves about 1e-4 relative and the path changes. R shows it too: with the fixed start `Asym = 103 + 1.4e-14`, R's `Asym` moves from 101.4679644 to 101.4687285 and `numIter` falls from 3 to 2. A 1e-15 start change in Python moves `Asym` by 7e-4. So the 9.4e-5 gap is floating-point path noise. A 1e-8 match needs bit-identical arithmetic in `Initialize`/`mixed_em`, the SSasymp gradient, the kernel, and PORT's difference step. Do not tune the start or the optimizer to hit R's value.
