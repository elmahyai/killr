Proof for `gls` with `corSymm` has two pitfalls. Neither is a Python logic gap.

- R's `glsApVar` returns the message string "Non-positive definite approximate variance-covariance" instead of a matrix when the Hessian is not negative definite. This happens on Loblolly `height ~ age`, `corSymm(~ 1 | Seed)`, with `natural = TRUE`. `as.numeric()` on that string gives `NA`, so the proof must flag the message case (as `gls-corsymm-r.R` and `gls-corsymm-py.py` do) and must not compare the string as numbers. Python returns the same message string, so the flags match.
- Oats `yield ~ Variety - 1` with `corSymm(~ 1 | Block)` (66 correlation parameters, 12 rows per block) makes R's nlminb stop with "function evaluation limit reached without convergence". Use a dataset with fewer correlation parameters (Loblolly has 15) for a fixed proof.
- Group order is part of the input. The built-in `Orthodont` has Subject levels `M16, M05, ...`, while `gls-orthodont.csv` sorts alphabetically. The log-likelihood sums over groups in level order, and the finite-difference apVar amplifies that rounding. Using the built-in data on the R side against the CSV fixture on the Python side gave a 1e-4 apVar gap, which was a proof-input mismatch and not a numerics bug. With the same CSV on both sides, `corSymm` natural = FALSE intervals match R within 7e-16. Keep the R and Python proofs on one data file and one level order.
