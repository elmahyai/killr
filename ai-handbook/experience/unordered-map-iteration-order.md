R isoband 0.3.0 orders its isoline and isoband output by the iteration order of a `std::unordered_map` keyed by grid point. The ring start and the line ids depend on it, so a Rust `HashMap` gives the same coordinates in a different order. Emulate libstdc++ instead: bucket counts 13, 29, 59, 127, ... (each the next prime at or above twice the last), new nodes at the front of an empty bucket, rehash that keeps list order, and `isobands` runs one contour pass at (0, 0) before its level loop, which changes the table size. See `crates/isoband/src/ordered_map.rs`; it matches R with zero difference.
